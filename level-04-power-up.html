Before the build · 20-minute anchor

The four patterns you'll use for the rest of your time in Qualtrics.

Level 04 opens with a 20-minute primer on integration patterns. Not because integrations are the point — but because you'll hit all four of these within your first year, and knowing which one you're using changes how you troubleshoot when something breaks.

🔌
Pattern 01

Connectors

Pre-built, configuration-only integrations to systems like Salesforce, ServiceNow, Workday, and Slack. No code. Set them up in the Qualtrics interface, map fields, and they run automatically on trigger conditions you define.

Best for When Qualtrics has a native connector to your system and you need standard field-mapping without custom logic.
Where it breaks Custom data transformations, non-standard system configurations, or endpoints the native connector doesn't support.
🔗
Pattern 02

Public APIs

REST API calls to the Qualtrics platform — or from Qualtrics to an external system. Flexible and powerful. Requires developer involvement unless your team has API-comfortable admins. The Qualtrics API is well-documented and versioned.

Best for Custom logic, non-native integrations, bulk operations, or pulling Qualtrics data into a data warehouse or BI tool.
Where it breaks Rate limits under high submission volumes, and anywhere you need real-time bidirectional sync — latency adds up.
📁
Pattern 03

Flat files

CSV or SFTP-based data exchange. Import contact lists, export response data, schedule batch uploads. Slower than API integrations but much simpler to set up and audit. Many HR and CRM systems export to flat files natively.

Best for Bulk contact imports, systems that don't have APIs, or teams that need a human-auditable data trail.
Where it breaks High-frequency updates (daily or more), anything requiring near-real-time data, and when files aren't consistently formatted.
⚡
Pattern 04

Event-driven workflows

Triggers in Qualtrics that fire in response to specific events — a survey response submitted, a ticket status changed, a score threshold crossed. The workflow you build in Level 04 uses this pattern: response submitted → ticket created → notification sent.

Best for Automated follow-up, closing the feedback loop, escalation workflows, and anything that needs to happen without a human in the middle.
Where it breaks Complex multi-condition logic, high-volume environments where trigger latency compounds, and anywhere you need guaranteed delivery order.
